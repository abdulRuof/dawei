# اختبار تحميل الباكند (Locust) + قاعدة البيانات (pgbench)

## 1) اختبار API بسيناريوهات مستخدمين حقيقية (Locust)

```bat
pip install locust
locust -f loadtest\locustfile.py --host http://localhost:8000
```

- افتح المتصفح على `http://localhost:8089`
- أدخل عدد المستخدمين (مثال: 50) ومعدّل الولادة (مثال: 5/ثانية)
- ابدأ الاختبار واتبع: **الطلبات/ثانية (RPS)**، **زمن الاستجابة 95% (P95)**، **الأخطاء %**

سيناريوهات مغطاة (مرجّحة تلقائيًا):
- سرد الأدوية (الأثقل — يفحص فهرس وN+1)
- البحث في الأدوية (يقطع في فهرس pg_trgm)
- تفاصيل صيدلية وسرد الصيدليات
- المناطق + نقطة الصحة

### أرقام مرجعية على جهاز متوسط (PostgreSQL محلي)
- استجابة `GET /api/pharmacies/` أو `GET /api/medicines` يجب ألا تتجاوز ~10-30ms مع 45 دواء.
- تحت 50 مستخدمًا: أهدافك الصحية P95 < 200ms وأخطاء 0%.

## 2) قاعدة البيانات وحدها (pgbench) — مدمجة مع PostgreSQL

اختبار الإدخال/القراءة الخام (بدون طبقة API):

```bat
pgbench -h localhost -p 5432 -U postgres -d dawei -c 20 -j 4 -T 60 -P 5
```

- `-c 20` عدد الاتصالات، `-j 4` عدد الخيوط، `-T 60` مدة 60 ثانية
- النتيجة: **TPS** (معاملة/ثانية). جهاز متوسط: 500-2000+ TPS طبيعي.

### فحوص يدوية سريعة
```bat
venv\Scripts\python.exe scripts\check_db.py     -- عدد الأدوية/الصيدليات والمخزون
venv\Scripts\python.exe scripts\_check_api.py   -- يتصل بـ :8000 ويتحقق من الاستجابات
```
